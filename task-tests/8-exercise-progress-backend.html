Contract these tests assume

Contract these tests assume

One new endpoint, GET api/exercise_progress.php, for the logged-in user only. It reads the user's completed workouts (workout_sessions.completed_at is not NULL) and their sets (workout_sets). No migration is needed.

Optional query parameters:

- from: First day included, YYYY-MM-DD (a real calendar date) (default: no start: all history).

- to: Last day included, YYYY-MM-DD (a real calendar date), the whole day counts (default: no end: all history).

- bucket: week (Monday to Sunday) or month (calendar month), for volume_trend (default: week).

Any other parameter is ignored. In particular there is no way to ask for another user's data.

Units and dates: weight is pounds (weight_lb). A workout's day is the America/New_York calendar date of its completed_at (the same zone workout_session.php uses for "today"; stored times are UTC, converted in PHP, so a 01:30 UTC finish counts as the evening before). The zone is fixed, so the browser sends nothing. from, to, the week and month buckets, PR dates and point dates all use these dates. Weeks start on Monday; period_start is the first day of the bucket, YYYY-MM-DD. Numbers are JSON numbers (135, 62.5), never strings. A value that cannot be worked out is null, never 0.


Definitions (agreed, and the only ones these tests use)

- Volume: the sum of weight_lb x reps over every set, in lb. A bodyweight set (0 lb) adds 0, the same as total_volume_lb in workout_history.php.

- Estimated 1RM (e1RM): Epley: weight_lb x (1 + reps / 30) per set, ignoring 0 lb sets. A workout's e1RM for an exercise is its best set's, rounded to 1 decimal (half up).

- first_e1rm_lb, last_e1rm_lb: the exercise's e1RM in the first and in the last workout of the range that has a weighted set of it. Both null unless there are at least 2 such workouts.

- strength_change_lb, strength_change_pct: last_e1rm_lb - first_e1rm_lb (can be negative); the percentage is that divided by first_e1rm_lb, x 100, 1 decimal. Both null when first_e1rm_lb is null.

- best_weight_lb: the heaviest weight lifted in the range for the exercise, null if every set was bodyweight.

- best_reps: the most reps in a single 0 lb (bodyweight) set in the range, null if the exercise had no 0 lb sets.

- Weight PR: in a workout where an exercise's heaviest weight is above 0 lb: a new PR when that weight is strictly greater than the heaviest weight in every earlier completed workout, of any date (not only the range).

- Rep PR (bodyweight): in a workout where an exercise's heaviest weight is 0 lb: a new PR when its most reps in one set is strictly greater than the most reps in one 0 lb set in every earlier completed workout, of any date.

- Both kinds of PR: the first time an exercise is ever logged is not a PR, a tie is not a PR, there is at most one PR per exercise per workout, and it counts when the workout is inside the range.

- points: per exercise, one entry per workout in the range that has the exercise, oldest first: {date, best_weight_lb, reps, e1rm_lb, best_reps, volume_lb}. best_weight_lb is the heaviest weight that workout, reps the most reps at that weight, e1rm_lb the best set's e1RM, volume_lb the workout's volume for the exercise. A workout whose heaviest weight is 0 lb is a bodyweight point: best_weight_lb, reps and e1rm_lb are null and best_reps is its most reps in one set; otherwise best_reps is null. Unfinished workouts are never points.

- strength_gain_pct (summary): (sum of last_e1rm_lb - sum of first_e1rm_lb) / sum of first_e1rm_lb x 100, 1 decimal, over the exercises that have a strength_change_lb; null if there are none.


Response (200)

Response 200: {from, to, bucket, summary: {workouts, sets, total_volume_lb, new_prs, strength_gain_pct}, exercises: [{exercise, sessions, sets, total_reps, volume_lb, best_weight_lb, best_reps, first_e1rm_lb, last_e1rm_lb, strength_change_lb, strength_change_pct, new_prs, points: [{date, best_weight_lb, reps, e1rm_lb, best_reps, volume_lb}]}], volume_trend: [{period_start, volume_lb, workouts}], prs: [{exercise, date, weight_lb, reps}]}

- exercises has every exercise logged in the range, A to Z; sessions is the number of workouts it appeared in.

- volume_trend starts at the bucket of the range's first workout and ends at the bucket of its last, oldest first, with a bucket for every period in between (volume_lb 0, workouts 0 when nothing was logged). It is [] when the range has no workouts.

- prs lists the new PRs in the range, newest day first, then by exercise name. For a weight PR, reps is the most reps done at that weight in that workout. For a rep PR, weight_lb is 0 and reps is the new best.

- Nothing is cut off: the response covers every completed workout in the range. The 100-workout limit of workout_history.php does not apply: every completed workout and set is read from the database for the user, and nothing is computed from that list.

Errors: 401 {"error":"Please log in."} when signed out; 405 {"error":"Method not allowed."} (with an Allow: GET header) for any other method; 400 {"error":"Invalid request.","errors":{...}} with one entry per bad parameter: errors.from / errors.to: Use a date like 2026-09-01., errors.to: The end date must be on or after the start date., errors.bucket: Use week or month.; 500 {"error":"Database error"} for a failed query.
