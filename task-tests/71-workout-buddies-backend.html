Rules

Rules

1. Invite method: one invite code, no email. A code is 8 characters, uppercase A to Z without I and O, and digits 2 to 9 (^[A-HJ-NP-Z2-9]{8}$), valid for 7 days. The server is strict: lowercase is a 400. The page uppercases what is typed before sending.

2. One group per person, enforced by a unique key, so two accepts at the same time make one row.

3. Names are shown as first name and last initial ("Olivia G."), the same shortening as api/leaderboard.php. No email or user id leaves the server. member_id is the id of the membership, not of the user.

4. An encouragement is plain text of 1 to 140 characters. The page shows it as text, never as HTML.

5. Messages and codes follow the existing API style: JSON only, times are ISO UTC ending in Z written by the server, and errors look like {"error": "..."} or {"error":"Invalid request.","errors":{...}}.

6. Not in this task: leaving a group, removing a member, a new code, a member limit, a rate limit on messages, email or push invites, and any frontend.

Who can do what

Who can do what

Accept an invite: any logged-in account that is not in a group and sends the code of a group whose code exists and has not expired. The owner does not approve.

See the members: only members of that group. Everyone else gets "group": null and learns nothing about the group.

See the invite code: only the owner. Every other member gets null.

Send an encouragement: a member of a group, to a different member of the same group.

Receive an encouragement: only the person it was sent to sees it. The sender sees the 201 reply only, and other members see nothing.

Create a group: any logged-in account that is not in a group. They become the owner.

Contract these tests assume

Contract these tests assume

Three new endpoints. The user always comes from the gymrank_session cookie. There is no way to ask for another user's data, and any user_id, email or other parameter sent is ignored.

api/buddy_group.php. GET returns the group view (200). POST {"create":true,"name":"Morning Lifters"} creates a group with the caller as owner (201, group view). The name is trimmed and must be 1 to 40 characters.

api/buddy_join.php. POST {"code":"7KQ2MXP9"} joins the group with that invite code (200, group view).

api/buddy_encourage.php. POST {"member_id":12,"message":"Great session today, keep it up!"} sends an encouragement to that member (201): {"encouragement":{"id":5,"to":"Ben C.","message":"Great session today, keep it up!","sent_at":"2026-11-13T15:04:05Z"}}. The message is trimmed and must be 1 to 140 characters (characters, not bytes).

The group view, the same shape every time a group is returned:

{"group":{"name":"Morning Lifters","member_count":3,"invite_code":null,"invite_expires_at":null,"members":[{"member_id":11,"name":"Olivia G.","is_me":false,"is_owner":true},{"member_id":12,"name":"Ben C.","is_me":false,"is_owner":false},{"member_id":15,"name":"Nina P.","is_me":true,"is_owner":false}]},"me":{"member_id":15,"is_owner":false},"encouragements":[{"id":4,"from":"Olivia G.","message":"Nice work on leg day!","sent_at":"2026-11-13T15:00:00Z"}]}

members are listed owner first, then by the time they joined. member_count is the number of members. me is the caller's own membership. encouragements are the last 20 sent to the caller, newest first. invite_code and invite_expires_at are filled in for the owner only (for example "7KQ2MXP9" and "2026-11-20T15:00:00Z") and are null for every other member.

With no group the body is {"group":null,"me":null,"encouragements":[]} with status 200. That is not an error.

Errors, all JSON, checked in this order: 401 {"error":"Please log in."}. 405 {"error":"Method not allowed."} with an Allow header (GET, POST on buddy_group.php; POST on the other two). 400 {"error":"Send a valid JSON object."} when the body is not JSON.

Join: 400 {"error":"Invalid request.","errors":{"code":"Enter the 8-character invite code."}} when the code is missing, not a string, or not 8 allowed characters. 409 {"error":"You are already in a workout buddies group."} when the caller is already in a group (this is checked before the code is looked up). 404 {"error":"That invite code isn't valid or has expired."} when no group has the code or its 7 days are over (the same message for both, so nobody can tell which).

Create: 400 {"error":"Invalid request.","errors":{"create":"Use true."}} when the body is not {"create":true,"name":...}. 400 with errors.name "Name your group in 1 to 40 characters." 409 {"error":"You are already in a workout buddies group."}.

Encourage: 400 with errors.member_id "Choose a member of your group." (missing or not a whole number) and errors.message "Write a message of 1 to 140 characters." 404 {"error":"Group not found."} when the caller has no group. 404 {"error":"Member not found."} when member_id is not a member of the caller's group. 400 with errors.member_id "You can't encourage yourself." when member_id is the caller's own.

Every endpoint: 500 {"error":"Database error"} when a query fails, with nothing half-saved.

Storage changes

Storage changes

New migration database/migrations/018_workout_buddies.sql. It only adds three tables, changes no existing row, and is safe to run more than once (IF NOT EXISTS). Its top comment says how to apply it locally, on aptitude and on cattle, like 015 does. All three tables are InnoDB, utf8mb4, with user ids BIGINT UNSIGNED like users.id.

buddy_groups: id (primary key, auto number), name VARCHAR(40) not null, owner_id (foreign key to users, deleted with the user), invite_code CHAR(8) not null with a unique key, invite_expires_at DATETIME (UTC) not null, created_at DATETIME (UTC) not null.

buddy_members: id (primary key, auto number, the member_id the API returns), group_id (foreign key to buddy_groups, deleted with the group), user_id not null with a unique key (this is what makes it one group per person), foreign key to users deleted with the user, joined_at DATETIME (UTC) not null. The owner has a member row like everyone else.

buddy_encouragements: id (primary key, auto number), group_id (foreign key to buddy_groups, cascade), sender_id and recipient_id (foreign keys to users, cascade), message VARCHAR(140) not null, created_at DATETIME (UTC) not null, and a key on (recipient_id, id) for the inbox.

Deleting an owner deletes their group, its members and its messages. That is acceptable for now because nothing in the app deletes accounts yet. Nothing is counted or stored beyond these rows: the member count and the inbox are read on every request.
