Contract these tests assume

Contract these tests assume

Units: weight is pounds (weight_lb, number, 0 to 1500, at most 2 decimal places, 0 = bodyweight). Reps is a whole number from 1 to 100. Times are set by the server only (any time the client sends is ignored) and are UTC strings like 2026-10-13T19:27:47Z. All responses are JSON; errors are {"error": "...", "errors"?: {...}}. The frontend already codes against the first three rows (src/workoutLog/workoutLogApi.js on branch 102-Daily-Logging-Frontend); the other rows are proposed here and need Nicholas's OK.

Endpoint: POST api/workout_sets.php. Request: {session_id, exercise, set_number, weight_lb, reps}. Success: {"set": {id, exercise, set_number, weight_lb, reps, logged_at, updated_at}}. Status: 201.

Endpoint: POST api/workout_sets.php. Request: {id, weight_lb, reps} (correction). Success: {"set": {...}}. Status: 200.

Endpoint: POST api/complete_workout.php. Request: {session_id}. Success: {session_id, completed_at}. Status: 200.

Endpoint: POST api/workout_session.php. Request: {} or {"day_position": 1}. Success: {"session": {...}}: creates today's session, or returns the unfinished (or already completed) one. Status: 201 new, 200 existing.

Endpoint: GET api/workout_session.php?id=N. Success: {"session": {...}}. Status: 200.

Endpoint: GET api/workout_history.php. Success: {"sessions": [...]} completed only, newest first. Status: 200.

session = {id, plan, name, focus, started_at, completed_at, exercises: [{name, sets: [{id, set_number, weight_lb, reps, logged_at, updated_at}]}], summary}. logged_at is when the set was first saved and never changes; updated_at is the last correction (equal to logged_at until corrected). summary is null until the workout is completed, then {exercise_count, set_count, total_reps, total_volume_lb, duration_seconds} (total_volume_lb = sum of weight × reps; exercise_count counts exercises with at least one set; duration_seconds = completed_at − started_at, a whole number). The user's current session is their most recent session that started today, finished or not: POST workout_session.php returns it (200), and creates a new one (201) only when there is none, so a user gets one workout per day. "Today" is the New York calendar date (UB's time zone), not the last 24 hours: at 12:00 AM New York time the previous day's session, finished or not, stops being current and the new day's workout can start. exercises come from the user's current plan day, in order. Without day_position the day is today's scheduled training day; on a rest day the server answers 409 {"error":"Rest day"}. day_position (1, 2, 3...) picks that plan day instead, so tests don't depend on the weekday. History item = {id, name, plan, started_at, completed_at, duration_seconds, exercise_count, set_count, total_volume_lb}, ordered by completed_at, newest first. Errors: 400 bad input (per-field errors.weight_lb / errors.reps), 401 not logged in, 404 unknown session or set (including another user's), 405 wrong method, 409 workout already completed, duplicate set, rest day or no workout plan selected, 415 body isn't JSON, 500 {"error":"Database error"}.
